# Reframing

## Description
A reframing suggestion offers a different interpretation of the problem that could change what the caller does next. It looks beneath repeated symptoms for an assumption about cause, ownership, value, or constraint. The new frame should remain connected to supplied evidence rather than becoming a clever slogan or motivational substitution. A useful reframe changes the available actions, boundaries, or tradeoffs in a recognizable way. It should be held as a lens to test, not asserted as certain fact. Use this category when changing the question or interpretation is more promising than repeating the current response.

## Why use / use cases
- [ ] **The same symptom keeps returning.** Repeated fixes may fail because the caller is solving the wrong problem or boundary. Use reframing when an alternate interpretation could explain the recurrence and change the intervention.
- [ ] **The problem is framed around activity instead of value.** Effort may be measured while the desired outcome remains untouched. Suggest a reframe when shifting attention to the beneficiary or result would alter the next move.
- [ ] **Ownership is assigned to the wrong place.** A team may be trying to control a condition it cannot influence or ignoring a leverage point it can. Use this category when a different boundary clarifies responsibility.
- [ ] **A constraint is treated as a fact rather than a design choice.** The caller may assume a fixed audience, sequence, resource, or quality bar. Recommend reframing when challenging that assumption opens a credible option.
- [ ] **The current labels hide a useful distinction.** One broad problem may contain different user needs, failure modes, or time horizons. Use a sharper frame when the distinction changes prioritization or evidence.
- [ ] **A conflict may be a measurement mismatch.** Parties can appear opposed because they optimize different definitions of success. Suggest a reframe when a shared outcome or explicit tradeoff can make the disagreement actionable.
- [ ] **A failure could be interpreted as information.** The result may reveal a weak premise, not just poor execution. Use reframing when treating it as evidence changes what should be tested next.
- [ ] **A new question could unlock a better experiment.** The caller may need to test a different causal claim before continuing. Recommend this category when the changed frame produces a discriminating, bounded check.

## Things to consider
- What symptom, assumption, boundary, or definition is being reframed?
- What evidence makes the alternate interpretation plausible?
- Which actions, owners, or tradeoffs change under the new frame?
- What part of the existing interpretation remains valid?
- Does the reframe explain more than the current account without overclaiming?
- What observation would support or challenge the new lens?
- What small question or experiment can distinguish the frames?
- What decision follows if the reframe is useful but not fully proven?

## When not to use
Do not use this category when the problem is already well-defined and only needs execution, evidence gathering, or a priority choice. Avoid it when the alternate frame is a metaphor with no changed action or when it merely renames the same problem. If many novel possibilities are needed, use creative exploration; if a tested mechanism comes from another field, use cross-domain.
