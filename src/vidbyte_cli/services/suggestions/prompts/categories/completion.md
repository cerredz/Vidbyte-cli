# Completion

## Description
A completion closes a specific unfinished obligation in the current task. It resolves a loose end that would otherwise leave the outcome incomplete.

## Goal
Bring the existing commitment to a recognizable and verifiable terminal state.

## Intent
Use this type when most work is done but an explicit requirement, check, artifact, or handoff remains.

## Timeline
Completion work is usually immediate because delay compounds ambiguity. It may move later only when a named dependency prevents closure.

## Checklist
- Point to the unfinished obligation.
- Explain why current evidence does not prove completion.
- Name the final verification or deliverable.

## Cautions
Do not broaden the task while trying to finish it. Avoid calling optional polish a completion requirement.
