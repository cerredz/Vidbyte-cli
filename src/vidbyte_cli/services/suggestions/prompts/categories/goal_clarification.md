# Goal Clarification

## Description
A goal-clarification suggestion makes an ambiguous desired outcome precise enough to act on. Its central move is to separate the result the caller wants from the activity currently consuming their attention, because those two drift apart quietly and the drift is invisible from inside the activity. A useful clarification names the audience, the value, the scope, and the stopping point wherever those details would change what gets built. It works by exposing interpretations that lead to different work or different measures of success, since an ambiguity that all readings resolve the same way costs nothing and needs no attention. The test of a clarification is whether it would have changed a decision. If every interpretation produces the same next action, the goal was clear enough.

Clarification is not a demand for certainty before anything can begin, and treating it that way turns a useful category into an obstacle. The suggestion should ask for the minimum additional precision that unblocks the next decision, not for a complete specification. It should name what evidence would show meaningful progress without requiring the outcome to be perfectly defined in advance. It should make value priorities explicit where speed, quality, cost, reach, safety, and learning are being traded silently, because an unstated hierarchy gets resolved by whoever acts first. It should give a stopping condition that makes the goal complete enough for this commitment, since open-ended standards invite unbounded polishing. It should also state which activity is being mistaken for the result, because naming that substitution is usually the whole of the insight.

## Why use
Use this category when the cost of proceeding is that the work might be excellent and wrong. Ambiguity about an outcome does not announce itself; it shows up later as a deliverable nobody wants, two teams building incompatible things, or a project that cannot end because nothing counts as finished. Each of those failures is expensive and each was cheap to prevent at the point where someone could have asked what success looks like. The category exists to make that question a normal move rather than an accusation.

It is also the correct response to a particular kind of stuckness that looks like a planning problem. When a caller cannot choose among options, cannot tell when to stop, or keeps admitting new scope, the usual instinct is to plan harder. Planning harder does not help, because the missing input is not a route but a destination. Clarifying the outcome resolves all three symptoms at once, which is why it is worth checking for before reaching for prioritization, strategy, or alternative.

Distinguish it from the categories it precedes. Prioritization chooses among commitments whose value is already understood, so it depends on clarity rather than supplying it. Strategy selects a direction that coordinates several actions, which presumes agreement about what the direction is for. Alternative compares routes to a fixed outcome, and without a fixed outcome the comparison is meaningless. Reframing changes how the problem is understood, which is a creative act, where clarification is a specifying one. Use goal clarification when a sharper statement of the outcome would visibly change the next decision.

## Use cases
- **The request describes activity, not a result.** The caller may be busy without knowing what change the work should produce. Name the outcome that makes the activity worth doing.
- **Stakeholders mean different things by success.** Hidden disagreement produces parallel work that nobody accepts. Surface one shared outcome or an explicit trade.
- **Scope keeps expanding.** New tasks get admitted because no boundary was ever drawn. State what is included, what is excluded, and what is sufficient.
- **The beneficiary is unclear.** Work may be optimized for the wrong person or decision-maker. Clarify when naming who must benefit would change the solution or the measure.
- **Nobody can tell when to stop.** Open-ended standards invite endless polishing or research. Define a recognizable threshold, acceptance condition, or review point.
- **Competing interpretations imply different moves.** The same phrase may support incompatible plans. Ask the question that separates them before execution compounds the error.
- **A broad goal is justifying unrelated work.** Loose language makes every nearby idea look relevant. Restate the central outcome so that unrelated work can be declined.
- **A value hierarchy is being applied silently.** Speed, quality, cost, reach, safety, and learning may be traded without anyone saying which leads. Make the priority explicit when it determines the route.
- **Success is stated as a number with no mechanism.** A target may exist without agreement on what would cause it. Clarify the outcome behind the metric before work optimizes the metric alone.
- **The same work is being redone under a new name.** Recurring effort often signals that the finish condition was never agreed. Define it once rather than negotiating it each time.
- **A constraint is being treated as the goal.** A deadline, a budget, or a compliance requirement may have displaced the outcome it was meant to protect. Restore the distinction.
- **Handover keeps failing.** Receivers rejecting work is often evidence that acceptance was never defined. Establish it with the receiver before more is produced.

## When not to use
- **The outcome is already clear.** Re-specifying a settled goal delays work without improving it.
- **The obstacle is execution, evidence, or capacity.** Precision does not help when everyone already knows what is wanted.
- **Clarification would only delay a low-risk action.** For cheap reversible work, acting produces the clarity faster.
- **Priorities conflict but the goal does not.** Competing clear goals is a different problem from one unclear goal.
- **The route is disputed rather than the destination.** Disagreement about how is not ambiguity about what.
- **Every interpretation leads to the same action.** An ambiguity with no consequence does not need resolving.

Route the suggestion elsewhere when one of those signals holds. Competing commitments belong to prioritization, and a disputed route belongs to alternative or strategy. Missing facts belong to investigation, and a doubtful claim belongs to verification. A missing capability belongs to learning or prerequisite, and a small reversible action that would settle the question faster than discussion belongs to immediate next steps. If the problem is that the current framing itself is unproductive, use reframing rather than sharpening the framing that is failing.
