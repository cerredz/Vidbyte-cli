# Goal Clarification

## Description
A goal-clarification suggestion makes an ambiguous desired outcome more precise. It separates the result the caller wants from the activity currently consuming attention. A useful clarification names the audience, value, scope, and stopping point where those details matter. It should expose interpretations that would lead to different work or different measures of success. Clarification is not a demand for perfect certainty before action. Use this category when a sharper outcome statement can materially improve the next decision or prevent wasted effort.

## Why use / use cases
- [ ] **The request describes activity but not a result.** The caller may be busy without knowing what change the work should create. Use this category to identify the outcome that makes the activity worthwhile.
- [ ] **Different stakeholders mean different things by success.** Hidden disagreement can produce parallel work that no one accepts. Suggest goal clarification when one shared outcome or an explicit tradeoff would align action.
- [ ] **The scope keeps expanding.** New tasks may be admitted because the boundary is undefined. Use the category to state what is included, excluded, and sufficient for this commitment.
- [ ] **The audience or beneficiary is unclear.** Work may be optimized for the wrong person or decision-maker. Recommend clarification when naming who must benefit changes the proposed solution or measure.
- [ ] **The caller cannot tell when to stop.** An open-ended standard invites endless polishing or research. Use this category to define a recognizable threshold, acceptance condition, or review point.
- [ ] **Competing interpretations imply different next moves.** The same phrase may support incompatible plans. Suggest a clarification question that separates those interpretations before execution compounds the error.
- [ ] **A goal is being used to justify unrelated ideas.** Broad language can make every adjacent opportunity appear relevant. Use this category to preserve the central outcome and reject work that does not serve it.
- [ ] **A decision needs a value hierarchy.** The caller may be trading speed, quality, cost, reach, safety, or learning without saying which matters most. Recommend clarification when making the priority explicit will determine the route.

## Things to consider
- What observable outcome should exist when the work succeeds?
- Who must experience, use, approve, or recognize that outcome?
- Which activity is being mistaken for the result?
- What scope boundary keeps the goal actionable?
- Which interpretations would produce different actions or measures?
- What tradeoff or value priority must be made explicit?
- What evidence can show meaningful progress without requiring perfection?
- What stopping condition makes the goal complete enough for this commitment?

## When not to use
Do not use this category when the desired outcome is already clear and the obstacle is execution, evidence, or capacity. Avoid it when clarification would only delay a low-risk action whose purpose is already understood. If the goal is clear but priorities conflict, use prioritization; if the route is disputed, use alternative or strategy.
