# Alternative

## Description
An alternative is a materially different route to the same desired outcome. It changes the method, sequence, resource mix, or scope boundary while keeping the intended result recognizable. Its value comes from exposing a credible option that the current path may hide. The comparison should use decision-relevant criteria instead of presenting an unranked list of possibilities. The suggestion should state the assumptions, transitions, and sacrifices required to adopt the different route. Use this category when the current approach is costly, blocked, risky, or resting on an untested premise.

## Why use / use cases
- [ ] **The current route has become expensive.** A different method may reach the same outcome with less time, money, or coordination. Suggest an alternative when the cost difference is large enough to justify comparing transition effort.
- [ ] **A key dependency is unavailable.** The chosen path may rely on a person, tool, supplier, permission, or data source that cannot be secured. Use this category when a different route can preserve the goal without pretending the dependency problem does not exist.
- [ ] **The current approach is producing weak results.** Repeating the same method is unlikely to improve an output whose failure comes from the method itself. Offer an alternative that changes the mechanism causing the poor result.
- [ ] **An important assumption is doubtful.** The plan may assume demand, capacity, access, or technical feasibility that has not been established. Use an alternative to make the decision robust to that uncertainty, not to avoid checking it.
- [ ] **Risk is concentrated in one design choice.** A second route may reduce exposure to a single point of failure or create a safer fallback. The suggestion should compare residual risks rather than label the new route automatically safer.
- [ ] **Sequence is causing avoidable friction.** Doing the same work in a different order may reduce waiting, rework, or handoffs. Recommend this category when the reordered path still protects prerequisites and completion criteria.
- [ ] **The goal can be met with a narrower commitment.** A smaller route may deliver the needed outcome without the full scope of the current plan. Use it when the reduced scope is an explicit tradeoff rather than an unacknowledged failure to meet the goal.
- [ ] **A different resource mix changes feasibility.** Borrowing expertise, automating a step, partnering, or using an existing asset may open a route the current team lacks. Suggest it when ownership and transition costs can be described concretely.

## Things to consider
- What outcome must remain invariant across the compared routes?
- Which mechanism, sequence, resource, or scope boundary actually changes?
- What evidence makes the alternative credible rather than merely imaginable?
- What transition cost must be paid before the alternative works?
- Which criteria decide between the current route and the alternative?
- What risks disappear, remain, or move under the different route?
- What assumption does each route require the decision-maker to accept?
- What is the smallest comparison or pilot that can distinguish the routes?

## When not to use
Do not use this category when the current route is merely unfinished and its assumptions remain sound; continuation or immediate next steps may be more appropriate. Avoid it when the proposed change is only a cosmetic variation or when no shared outcome has been defined. If the real need is to generate many novel possibilities, use creative exploration, and if one direction must be chosen across several actions, use strategy.
